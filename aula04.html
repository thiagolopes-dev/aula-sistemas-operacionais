Shell script é a linguagem que já está instalada em todo servidor Linux do planeta. Não precisa compilar, não precisa instalar nada. Abre o editor e roda.

As próximas seis aulas são disso. É o coração prático do semestre.

aluno@linux:~$ nano meuprimeiroscript.sh

Anatomia de um script

#!/bin/bash # Isto é um comentário # exibe_mensagem echo "Sou uma mensagem" # Variavel nome="Meu nome é Thiago" sobrenome="Lopes" texto="e tenho" idade="29 anos" # chamando_variaveis echo $nome $sobrenome $texto $idade

Três elementos e nada mais: a primeira linha que diz quem executa, os comentários que explicam, e os comandos que fazem.

aluno@linux:~$ head -1 script.sh

A primeira linha: shebang

O #! seguido do caminho diz ao sistema qual programa deve interpretar o arquivo. Sem ela, o comportamento depende de quem chamou.

#!/bin/bash

Bash completo. Tem arrays, [[ ]], $(( )) e tudo que vamos usar.

Use sempre este.

#!/bin/sh

Shell mínimo. Vários recursos do bash não funcionam — e o erro que aparece não diz qual é o problema real.

# testandoread.sh começa com #!/bin/sh # funciona hoje, porque só usa echo e read. # No dia em que ganhar um array, quebra sem avisar o motivo.
aluno@linux:~$ chmod +x script.sh && ./script.sh

Fazendo rodar

# 1. criar aluno@linux:~$ nano meuprimeiroscript.sh # 2. dar permissão de execução aluno@linux:~$ chmod +x meuprimeiroscript.sh # 3. executar aluno@linux:~$ ./meuprimeiroscript.sh Sou uma mensagem Meu nome é Thiago Lopes e tenho 29 anos
Duas coisas que confundem no começo

O ./ é obrigatório. Sem ele, o shell procura o comando nas pastas do sistema e não no diretório atual. Digitar só meuprimeiroscript.sh dá "comando não encontrado".

Sem chmod +x, é só texto. A permissão de execução é o que transforma o arquivo em programa. Alternativa sem permissão: bash meuprimeiroscript.sh.

aluno@linux:~$ nome="valor"

Variáveis

# atribuição: SEM espaço em volta do igual nome="Thiago" idade=29 nome = "Thiago" # ERRO: o shell entende "nome" como um comando a executar # uso: sempre com cifrão echo $nome echo "Olá, $nome" echo "${nome}Lopes" # chaves marcam onde o nome termina
Aspas: a regra prática

Duplas expandem variáveis — "$nome" vira Thiago.
Simples não expandem nada — '$nome' vira literalmente $nome.
Na dúvida, use duplas. E use sempre alguma.

aluno@linux:~$ nano info.sh

Script útil já na primeira aula

#!/bin/bash echo "Seu nome de usuário é:" whoami echo "Info de hora atual e tempo que o computador está ligado:" uptime echo "O script está executando do diretorio:" pwd

Repare no que este script é: três comandos que você já digitava à mão, agora em um arquivo. É literalmente isso que shell script faz — guarda o que você repetiria.

Melhoria imediata: troque as chamadas soltas por $(comando) e monte frases completas. Vamos fazer isso no laboratório.

aluno@linux:~$ data=$(date)

Guardando a saída de um comando

O $( ) executa o comando e devolve o resultado como texto. É o que liga shell script ao resto do sistema.

#!/bin/bash usuario=$(whoami) pasta=$(pwd) data=$(date '+%d/%m/%Y') hora=$(date '+%H:%M') arquivos=$(ls | wc -l) echo "Olá $usuario!" echo "Hoje é $data, agora são $hora." echo "Você está em $pasta e há $arquivos itens aqui."
Olá thiago! Hoje é 31/08/2026, agora são 20:14. Você está em /home/thiago e há 7 itens aqui.

Comentários

# comentário de uma linha # bloco de várias linhas: : <<'COMENTARIO' echo "teste1" echo "teste2" COMENTARIO # o delimitador de abertura e o de fechamento # precisam ser EXATAMENTE iguais
Um erro real, para vocês verem funcionando

Se você abrir com 'BLOCO COMENTARIO' e fechar com COMENTARIO, os delimitadores não batem. O bash procura o fechamento até o fim do arquivo e avisa:

warning: here-document delimited by end-of-file

O script roda mesmo assim — e é justamente por isso que o aviso passa despercebido. Funcionar não é o mesmo que estar certo.

aluno@linux:~$ ./pratica.sh
