Usuários e grupos

O sistema não conhece pessoas — conhece números. UID identifica o usuário, GID identifica o grupo. Nome é conveniência nossa.

$ id uid=1000(thiago) gid=1000(thiago) grupos=1000(thiago),27(sudo) $ grep $(whoami) /etc/passwd thiago:x:1000:1000::/home/thiago:/bin/bash nome ↑ uid gid home shell # todos os grupos da máquina $ cut -d: -f1 /etc/group | sort

O x na segunda posição significa que a senha não está aqui — está em /etc/shadow, que só o root lê. Tente cat /etc/shadow e veja o que acontece.

Primeiro caractere

Três blocos de três

Sempre nesta ordem: dono, grupo, outros. Cada bloco responde: ler, escrever, executar.

O sistema aplica o primeiro bloco que combina. Se você é o dono, valem as permissões de dono — mesmo que "outros" tenha mais direitos.

aluno@linux:~$ chmod 750 arquivo

A notação octal

r = 4

Ler o arquivo, ou listar o diretório.

w = 2

Alterar o arquivo, ou criar e apagar dentro do diretório.

x = 1

Executar o script, ou entrar no diretório.

OctalSimbólicoPara quê
755rwxr-xr-xScript que todos podem executar.
750rwxr-x---Script da equipe. Fora do grupo, ninguém toca.
644rw-r--r--Arquivo de texto comum. Script assim não roda.
600rw-------Segredos: senhas, chaves, credenciais.
777rwxrwxrwxNunca. Isso é render-se, não configurar.
aluno@linux:~$ chmod u+x / chmod 755

chmod — as duas notações

# octal: define TUDO de uma vez chmod 755 backup.sh chmod 600 .credenciais # simbólica: altera SÓ o que você indicar chmod u+x backup.sh # dá execução ao dono chmod g-w relatorio.txt # tira escrita do grupo chmod o= segredo.txt # zera para outros chmod a+r publico.txt # leitura para todos # recursivo — aplica em tudo abaixo chmod -R 750 ~/scripts # todos os .sh de uma vez chmod +x *.sh

Destino: u dono, g grupo, o outros, a todos. Operador: + adiciona, - remove, = define exatamente.

aluno@linux:~$ sudo chown usuario:grupo arquivo

chown — mudando o dono

# ver os grupos disponíveis cat /etc/group cut -d: -f1 /etc/group | sort # mudar dono e grupo sudo chown servidor:servidor estudo # só o dono sudo chown appuser arquivo.txt # só o grupo sudo chgrp devs arquivo.txt # recursivo — o padrão de deploy sudo chown -R appuser:appuser /opt/projeto

Mudar o dono exige sudo, e há um motivo lógico: se você pudesse dar um arquivo seu para outro usuário, poderia plantar arquivo no nome dele. Só o administrador transfere propriedade.

Laboratório · sentindo na pele

# 1. crie um script e tente rodar sem permissão $ echo '#!/bin/bash' > teste.sh $ echo 'echo "funcionou"' >> teste.sh $ ./teste.sh bash: ./teste.sh: Permissão negada $ ls -l teste.sh -rw-r--r-- ← falta o x $ chmod +x teste.sh && ./teste.sh funcionou # 2. agora crie outro usuário e teste como ele $ sudo adduser teste $ chmod 700 teste.sh $ sudo -u teste ./teste.sh Permissão negada # 700 = só o dono $ chmod 755 teste.sh $ sudo -u teste ./teste.sh funcionou
aluno@linux:~$ umask

Por que o script nasce sem x

Todo arquivo novo recebe uma permissão padrão. A umask é a máscara que subtrai desse padrão.

$ umask 0022 # arquivos: 666 - 022 = 644 ← sem x, nunca # diretórios: 777 - 022 = 755 $ touch novo.sh && ls -l novo.sh -rw-r--r-- # mais restritivo: nada para grupo e outros $ umask 077 && touch privado.txt && ls -l privado.txt -rw-------

Aí está a resposta: arquivos nunca nascem executáveis, por segurança. Se nascessem, qualquer coisa baixada da internet chegaria pronta para rodar.
