O comando read

#!/bin/bash #Entre com seu nome echo "Digite seu nome" #READ read nome echo "Bem vindo $nome no terminal Linux"
# versão mais enxuta: pergunta e lê na mesma linha read -p "Digite seu nome: " nome # dois valores de uma vez, separados por espaço read -p "Nome e idade: " nome idade # senha: não mostra o que está sendo digitado read -sp "Senha: " senha echo # o echo vazio pula a linha depois do -s

O -s é o mesmo comportamento do sudo quando pede senha: nem asterisco aparece. Todo script que pede senha deve usar.

aluno@linux:~$ ./script.sh valor1 valor2

Argumentos: entrada sem perguntar

#!/bin/bash echo "Nome do script: $0" echo "Primeiro: $1" echo "Segundo: $2" echo "Quantos vieram: $#" echo "Todos juntos: $@"
aluno@linux:~$ ./exemplo.sh Thiago 29 Nome do script: ./exemplo.sh Primeiro: Thiago Segundo: 29 Quantos vieram: 2 Todos juntos: Thiago 29
Quando usar cada um

read exige alguém na frente do teclado. $1 não.

Script que vai rodar sozinho, agendado — e vocês vão escrever vários — não pode usar read. Ele ficaria esperando para sempre.

aluno@linux:~$ echo $(( 2 + 2 ))

Contas em shell

Variáveis em shell são texto por padrão, não número. Para o shell, "10" + "5" não significa nada — é preciso pedir explicitamente uma operação aritmética.

x=10 y=3 echo $(( x + y )) # 13 echo $(( x - y )) # 7 echo $(( x * y )) # 30 echo $(( x / y )) # 3 ← divisão INTEIRA echo $(( x % y )) # 1 ← resto echo $(( x ** 2 )) # 100 ← potência # atribuindo direto — o soma.sh de vocês (( sum = 25 + 35 )) echo $sum # 60 # incremento, muito usado em laços contador=$(( contador + 1 ))
aluno@linux:~$ echo "scale=2; 10/3" | bc

Números com vírgula

O shell só faz conta com inteiros. Para decimais, existe o bc — uma calculadora à parte que recebe a expressão pela entrada padrão.

# sem bc echo $(( 10 / 3 )) 3 # com bc: scale define as casas decimais echo "scale=2; 10/3" | bc 3.33 # usando variáveis preco=49.90 qtd=3 total=$(echo "scale=2; $preco * $qtd" | bc) echo "Total: R$ $total" Total: R$ 149.70

Se o bc não estiver instalado: sudo apt install bc.

aluno@linux:~$ nano calculadora1.sh

Montando a calculadora

#!/bin/bash echo "Digite um número" read num1 echo "Digite outro número" read num2 resultado=$(( num1 + num2 )) echo "A soma dos números é: $resultado"
Sobre a sintaxe antiga

Você vai encontrar $[ num1+num2 ] em código pela internet — inclusive em exemplos meus antigos. Funciona, mas está obsoleto há mais de vinte anos e pode sumir em versões futuras do bash.

Use sempre $(( )). Duplos parênteses.

aluno@linux:~$ printf "%.2f\n" 3.14159

Formatando a saída

O echo resolve quase tudo. Quando a apresentação importa, o printf dá controle.

# echo simples echo "Total: $valor" # printf com formatação printf "Total: R$ %.2f\n" "$valor" Total: R$ 149.70 # alinhando colunas — útil em relatórios printf "%-15s %8s\n" "Produto" "Preço" printf "%-15s %8.2f\n" "Teclado" 150.00 printf "%-15s %8.2f\n" "Monitor" 899.90 Produto Preço Teclado 150.00 Monitor 899.90

%-15s = texto alinhado à esquerda em 15 colunas. %8.2f = número com 2 decimais em 8 colunas. O \n é a quebra de linha, que o printf não coloca sozinho.

aluno@linux:~$ bash -x script.sh

Quando não funcionar

# mostra cada linha antes de executar, com as variáveis já substituídas aluno@linux:~$ bash -x calculadora1.sh + echo 'Digite um número' + read num1 + read num2 + resultado=15 + echo 'A soma dos números é: 15' # verifica a sintaxe SEM executar aluno@linux:~$ bash -n calculadora1.sh

O -x é a ferramenta número um de depuração em shell. Quando o script faz algo que você não esperava, ele mostra exatamente o que o shell entendeu — que costuma ser diferente do que você escreveu.

aluno@linux:~$ ./pratica.sh
