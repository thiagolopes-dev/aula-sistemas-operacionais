Três scripts que qualquer administrador de sistema tem na máquina: relatório, monitoramento e backup. Vocês vão sair com os três funcionando.

aluno@linux:~$ cat comandos-de-informacao.md

De onde vêm os dados

ComandoDevolve
whoami / hostnameQuem sou e em qual máquina.
uptimeHá quanto tempo está ligada e a carga atual.
df -h /Espaço em disco.
free -hMemória usada e disponível.
nprocQuantos núcleos de processador.
ps auxTudo que está rodando.
ss -tlnQuais portas estão escutando.
whoQuem está conectado.

Todos devolvem texto — e é por isso que shell script funciona tão bem em administração: tudo que o sistema informa pode ser capturado com $( ), filtrado com grep e cortado com cut.

aluno@linux:~$ df -h / | tail -1 | awk '{print $5}'

Extraindo só o que interessa

# a saída bruta tem cabeçalho e várias colunas $ df -h / Sist.Arq. Tam. Usado Disp. Uso% Montado /dev/sda1 117G 1,9G 109G 2% / # tail -1 tira o cabeçalho $ df -h / | tail -1 # awk pega a coluna 5 $ df -h / | tail -1 | awk '{print $5}' 2% # tr tira tudo que não for número $ df -h / | tail -1 | awk '{print $5}' | tr -dc '0-9' 2 # agora dá para comparar num if uso=$(df -h / | tail -1 | awk '{print $5}' | tr -dc '0-9') if [ "$uso" -gt 80 ]; then echo "ALERTA"; fi

Essa cadeia — gerar, cortar, limpar, comparar — é o padrão de praticamente todo script de monitoramento.

aluno@linux:~$ ./relatorio.sh

Script 1 · Relatório do sistema

#!/bin/bash # relatorio.sh — o info.sh da aula 4, crescido linha() { printf "%-22s %s\n" "$1" "$2"; } echo "==========================================" echo " RELATÓRIO DO SISTEMA" echo " $(date '+%d/%m/%Y às %H:%M')" echo "==========================================" linha "Usuário:" "$(whoami)" linha "Máquina:" "$(hostname)" linha "Diretório:" "$(pwd)" linha "Ligada há:" "$(uptime -p)" linha "Núcleos:" "$(nproc)" linha "Memória:" "$(free -h | awk 'NR==2{print $3\" de \"$2}')" linha "Disco:" "$(df -h / | tail -1 | awk '{print $3\" de \"$2\" (\"$5\")\"}')" linha "Conectados:" "$(who | wc -l)" echo "=========================================="
aluno@linux:~$ ./monitora.sh

Script 2 · Monitoramento com alerta

#!/bin/bash set -u LOG="$HOME/monitor.log" LIMITE_DISCO=80 LIMITE_MEM=90 log() { echo "[$(date '+%F %T')] $1" >> "$LOG"; } disco=$(df -h / | tail -1 | awk '{print $5}' | tr -dc '0-9') mem=$(free | awk 'NR==2{printf "%.0f", $3/$2*100}') carga=$(cut -d' ' -f1 /proc/loadavg) log "disco=${disco}% memoria=${mem}% carga=$carga" if [ "$disco" -gt "$LIMITE_DISCO" ]; then log "ALERTA: disco acima de ${LIMITE_DISCO}%" du -sh "$HOME"/* 2>/dev/null | sort -rh | head -5 >> "$LOG" fi if [ "$mem" -gt "$LIMITE_MEM" ]; then log "ALERTA: memória acima de ${LIMITE_MEM}%" fi

Repare: quando o disco passa do limite, ele já registra os cinco maiores culpados. Script bom não só avisa — adianta a investigação.

aluno@linux:~$ ./backup.sh

Script 3 · Backup

#!/bin/bash set -u ORIGEM="$HOME/scripts" DESTINO="$HOME/backups" DATA=$(date +%Y%m%d_%H%M%S) LOG="$HOME/backup.log" log() { echo "[$(date '+%F %T')] $1" | tee -a "$LOG"; } if [ ! -d "$ORIGEM" ]; then log "ERRO: origem $ORIGEM não existe" exit 1 fi mkdir -p "$DESTINO" log "Iniciando backup de $ORIGEM" if tar -czf "$DESTINO/backup_$DATA.tar.gz" -C "$HOME" scripts; then tamanho=$(du -h "$DESTINO/backup_$DATA.tar.gz" | cut -f1) log "Concluído: backup_$DATA.tar.gz ($tamanho)" else log "ERRO: falha ao compactar" exit 2 fi # mantém só os 5 mais recentes ls -t "$DESTINO"/backup_*.tar.gz | tail -n +6 | xargs -r rm -- log "Limpeza concluída"
aluno@linux:~$ tar -czf / tar -xzf

Compactando e restaurando

# criar arquivo compactado tar -czf backup.tar.gz pasta/ # │││ # ││└─ f: nome do arquivo # │└── z: compacta com gzip # └─── c: criar # ver o conteúdo SEM extrair tar -tzf backup.tar.gz # extrair tar -xzf backup.tar.gz # └─── x: extrair # extrair para outro lugar tar -xzf backup.tar.gz -C /tmp/teste
Backup que ninguém testou não é backup

A regra da profissão: sempre extraia e confira antes de confiar. Backup corrompido descoberto no dia do desastre é pior que não ter backup — porque você contava com ele.

aluno@linux:~$ tee -a arquivo.log

Registrando o que aconteceu

# só no arquivo echo "mensagem" >> log.txt # na tela E no arquivo ao mesmo tempo echo "mensagem" | tee -a log.txt # a função de log que vale a pena copiar log() { local nivel="$1" local msg="$2" echo "[$(date '+%F %T')] [$nivel] $msg" | tee -a "$LOG" } log INFO "Processo iniciado" log ERRO "Arquivo não encontrado" log AVISO "Disco em 85%"

Data, nível e mensagem. É o formato que você vai reencontrar em novembro, quando o log do sistema entrar na conversa.

Roteiro do laboratório
  • 01Implemente o relatorio.sh e acrescente duas informações à sua escolha.
  • 02Monte a cadeia que extrai só o número do uso de disco e teste no if.
  • 03Implemente o monitora.sh, baixe o limite para 1% e confirme o alerta no log.
  • 04Implemente o backup.sh e execute.
  • 05Teste o backup: extraia em /tmp e confirme que os arquivos estão íntegros.
  • 06Rode o backup seis vezes e verifique se a limpeza manteve só os cinco mais recentes.
