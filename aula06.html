A estrutura if

#!/bin/bash echo "Digite um número qualquer:" read numero if [ $numero -ge 20 ]; then echo "este número é maior ou igual a 20" else echo "este número é menor que 20" fi

As palavras

if · then · elif · else · fi

fi é if escrito ao contrário. A mesma brincadeira aparece em case / esac.

O ponto e vírgula

then é uma instrução separada. Na mesma linha do if, precisa de ; antes. Em linha própria, dispensa.

Os espaços dentro dos colchetes são obrigatórios. [ é um comando, e comando precisa estar separado dos argumentos. [$x -ge 20] dá erro.

aluno@linux:~$ man test

Operadores de teste

Números

-eq igual · -ne diferente

-gt maior · -ge maior ou igual

-lt menor · -le menor ou igual

Texto

= iguais · != diferentes

-z está vazio · -n não está vazio

Arquivos

-e existe · -f é arquivo · -d é diretório

-r posso ler · -w posso escrever · -x posso executar · -s não está vazio

Combinando

&& e · || ou · ! negação

if [ -f "$a" ] && [ -r "$a" ]; then

A armadilha que pega todo mundo

-eq compara números. = compara texto. Trocar os dois não dá erro — dá resultado errado em silêncio.

[ "01" = "1" ] é falso. [ 01 -eq 1 ] é verdadeiro.

Vários caminhos: elif

#!/bin/bash read num1; read num2 echo "1-Somar 2-Subtrair 3-Multiplicar 4-Dividir" read equacao if [ $equacao -eq 1 ]; then resultado=$(( num1 + num2 )) elif [ $equacao -eq 2 ]; then resultado=$(( num1 - num2 )) elif [ $equacao -eq 3 ]; then resultado=$(( num1 * num2 )) elif [ $equacao -eq 4 ]; then resultado=$(( num1 / num2 )) else echo "Opção inválida" fi echo "O resultado é: $resultado"

Este script funciona. E tem três defeitos.

Rodem com a opção 9. Depois com 10 e 0. Cinco minutos.

aluno@linux:~$ bash calculadora2.sh

Os três defeitos

# opção inválida $ bash calculadora2.sh 10 / 5 / 9 Opção inválida O resultado é: ← vazio, e ninguém reclamou # divisão por zero calculadora2.sh: division by 0 # divisão comum 10 / 3 = 3 ← divisão inteira
  • 01O echo final está fora do if. Roda sempre, mesmo quando a variável não foi criada. O shell trata variável inexistente como texto vazio e segue em frente.
  • 02Divisão por zero derruba o script. Falta testar antes.
  • 03Divisão inteira. Não é bug, é como o shell funciona — mas o usuário não sabe disso.
aluno@linux:~$ case $var in ... esac

A versão corrigida, com case

#!/bin/bash set -u # variável indefinida vira ERRO read -p "Primeiro número: " num1 read -p "Segundo número: " num2 echo "1-Somar 2-Subtrair 3-Multiplicar 4-Dividir" read -p "Opção: " opcao case "$opcao" in 1) resultado=$(( num1 + num2 )) ;; 2) resultado=$(( num1 - num2 )) ;; 3) resultado=$(( num1 * num2 )) ;; 4) if [ "$num2" -eq 0 ]; then echo "Não dá para dividir por zero"; exit 1 fi resultado=$(echo "scale=2; $num1/$num2" | bc) ;; *) echo "Opção inválida"; exit 1 ;; esac echo "Resultado: $resultado"

O ;; fecha cada caso. O *) é o "qualquer outra coisa". Muito mais legível que a corrente de elif — e é o padrão que o systemctl usa por dentro.

aluno@linux:~$ echo $?

O código de saída

Todo comando devolve um número ao terminar. Zero é sucesso; qualquer outro valor é erro. É assim que o if decide de verdade.

$ ls /home > /dev/null; echo $? 0 $ ls /naoexiste 2> /dev/null; echo $? 2 # testando um COMANDO direto, sem colchetes if ping -c1 8.8.8.8 > /dev/null 2>&1; then echo "Internet funcionando" else echo "Sem conexão" fi # o seu script também devolve código exit 0 # deu certo exit 1 # deu errado

Invertido em relação a outras linguagens, e faz sentido: só existe um jeito de dar certo, e muitos de dar errado. Cada número identifica um erro diferente.

Os cinco problemas

  • 01Credencial dentro do código. Um cat login.sh revela a senha. Quem lê o arquivo entra.
  • 02Senha em texto puro. Deveria comparar o hash, nunca a senha em si.
  • 03read sem -s. A senha aparece na tela, à vista de quem está atrás.
  • 04Dado pessoal no arquivo. Se isso for para o GitHub, o CPF vai junto — e histórico de commit não se apaga.
  • 05Variáveis sem aspas. Entrada com espaço ou caractere especial pode alterar o teste.
