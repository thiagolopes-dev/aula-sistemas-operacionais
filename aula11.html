Seu backup só roda
quando você lembra.
Ou seja: nunca.

Hoje os scripts ganham a última capacidade que falta — rodar sozinhos, no horário certo, sem ninguém na frente do teclado.

aluno@linux:~$ crontab -e

Os cinco campos

┌───── minuto (0-59) │ ┌─── hora (0-23) │ │ ┌─ dia do mês (1-31) │ │ │ ┌─ mês (1-12) │ │ │ │ ┌─ dia da semana (0-7, domingo = 0 ou 7) │ │ │ │ │ * * * * * comando a executar
*/5 * * * * /home/thiago/monitora.sh # a cada 5 minutos 0 3 * * * /home/thiago/backup.sh # todo dia às 3h 0 0 * * 0 /home/thiago/semanal.sh # domingo à meia-noite 30 8 1 * * /home/thiago/mensal.sh # dia 1, às 8h30 0 9-18 * * 1-5 /home/thiago/hora.sh # de hora em hora, dias úteis

O * é "qualquer valor". O */5 é "de 5 em 5". O 9-18 é intervalo. O 1-5 em dia da semana é segunda a sexta.

aluno@linux:~$ crontab -l

Gerenciando os agendamentos

crontab -e # editar (abre o editor padrão) crontab -l # listar o que está agendado crontab -r # remover TUDO — cuidado, não pergunta
Duas armadilhas de digitação

O -r fica ao lado do -e. Um deslize e você apaga todos os agendamentos sem confirmação. Antes de editar, faça: crontab -l > ~/cron-backup.txt

A última linha precisa terminar com Enter. Sem quebra de linha no final, o cron ignora a última entrada em silêncio.

# restaurar a partir do backup crontab ~/cron-backup.txt
aluno@linux:~$ env -i bash

Por que o script falha no cron

Funciona quando você roda à mão, não funciona agendado. É o erro número um de shell script — e a causa é sempre a mesma.

O cron roda com ambiente mínimo

O $PATH dele tem quase nada. As variáveis do seu .bashrc não existem lá. O diretório de trabalho não é o seu home.

Vocês já viram isso acontecer nesta disciplina: na Aula 03, o script que criou os usuários falhou com groupadd: comando não encontrado. O comando existia — o PATH daquele shell é que não alcançava /usr/sbin.

# veja a diferença você mesmo $ echo $PATH /usr/local/bin:/usr/bin:/bin:/usr/local/games... $ env -i bash -c 'echo $PATH' /usr/bin:/bin ← é isso que o cron enxerga
aluno@linux:~$ cat script-a-prova-de-cron.sh

As quatro defesas

#!/bin/bash set -u # 1. fixe o PATH export PATH="/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin" # 2. defina as variáveis que você precisa HOME_DIR="/home/thiago" LOG="$HOME_DIR/backup.log" # 3. use caminhos absolutos, sempre cd "$HOME_DIR" || exit 1 # 4. registre tudo, inclusive erros echo "[$(date '+%F %T')] iniciando" >> "$LOG"
# e no crontab, capture a saída COMPLETA */5 * * * * /home/thiago/monitora.sh >> /home/thiago/cron.log 2>&1 # ↑ # sem isso, o erro some para sempre
aluno@linux:~$ grep CRON /var/log/syslog

Descobrindo se rodou

# o sistema registra cada execução do cron grep CRON /var/log/syslog | tail -10 # em algumas distribuições journalctl -u cron --since "1 hour ago" # o seu próprio log é o mais confiável tail -f ~/cron.log
Método de teste que economiza horas

1. Agende para daqui a 2 minutos, não para as 3 da manhã.

2. Confirme no log que rodou e deu certo.

3. Só então mude para o horário real.

Ninguém deveria descobrir que o backup nunca rodou no dia em que precisou dele.

aluno@linux:~$ ./automatizado.sh

Rotina completa de automação

#!/bin/bash # manutencao.sh — roda sozinho todo dia set -u export PATH="/usr/local/bin:/usr/bin:/bin" BASE="/home/thiago" LOG="$BASE/manutencao.log" log() { echo "[$(date '+%F %T')] $1" >> "$LOG"; } log "=== início da manutenção ===" # 1. backup dos scripts tar -czf "$BASE/backups/scripts_$(date +%Y%m%d).tar.gz" \ -C "$BASE" scripts 2>> "$LOG" \ && log "backup ok" || log "backup FALHOU" # 2. checagem de disco uso=$(df -h / | tail -1 | awk '{print $5}' | tr -dc '0-9') log "disco em ${uso}%" [ "$uso" -gt 80 ] && log "ALERTA: disco alto" # 3. limpeza de backups antigos find "$BASE/backups" -name "*.tar.gz" -mtime +7 -delete log "=== fim ==="
aluno@linux:~$ ./pratica.sh

Roteiro do laboratório
  • 01Faça backup do seu crontab antes de qualquer coisa.
  • 02Agende o monitora.sh da Aula 09 para rodar a cada 2 minutos.
  • 03Espere e confirme no log que rodou.
  • 04Quebre de propósito: tire o export PATH e chame df sem caminho absoluto. Veja falhar no cron e funcionar na mão.
  • 05Conserte aplicando as quatro defesas e confirme.
  • 06Implemente o manutencao.sh completo e agende para o horário que quiser.
  • 07Remova os agendamentos de teste com crontab -e — não com -r.
